# Argo CD 개인 계정 운영

2026-09-08 사용자 결정: 기본 `admin`은 초기 설정에만 사용하고, 이후 개발자별 개인 계정을 발급한다. 공유 개발자 계정은 만들지 않는다. 현재 방향은 로컬 개인 계정이며 SSO 도입은 별도 결정이다.

현재는 정책 문서와 [계정 입력/Helm values 생성 도구](../../gitops/platform/argocd/README.md), [2단계 초기 admin bootstrap](argocd-bootstrap.md) 코드를 준비했다. 2단계 코드의 Argo CD 기준은 v3.5.2이며 초기 admin 비밀값만 Doppler 주입으로 생성한다. 개발자 명단·계정명·담당 프로젝트·개인 관리자 담당자와 개인 계정 비밀번호 주입/교체 경로는 아직 미확정이다. 실제 계정 생성·비밀번호 발급·admin 비활성화는 수행하지 않았다.

코드의 현재 개발자 역할은 명시한 프로젝트의 조회 전용이다. 더 많은 권한은 자동 부여하지 않는다. 생성 기본값은 bootstrap·빈 계정 목록이며, 입력 구조와 생성물은 Git에서 함께 검토한다. 코드 검증 기록은 실제 로그인/권한 검증을 대체하지 않는다.

## 관리 원본과 권한

- [Argo CD 설정 경로](../../gitops/platform/argocd/README.md)의 Git 원본에서 `argocd-cm`의 로컬 계정 정의·활성화 여부와 `argocd-rbac-cm`/AppProject의 권한을 관리한다. 반영 주체는 Argo CD다.
- 사람 계정은 `login` capability를 기본으로 설계한다. 토큰 발급용 `apiKey` capability는 필요성이 확인된 계정에만 부여한다. CI/자동화 계정은 사람 계정과 분리하고 필요할 때만 만든다.
- 일반 개발자에게 관리자 권한을 일괄 부여하지 않는다. 실제 담당 프로젝트·앱과 필요한 동작을 확인해 명시적으로 권한을 부여한다. 기본 정책은 최소 권한이며 익명 접근은 허용하지 않는다.
- 내장 `role:readonly`도 모든 리소스에 대한 읽기 권한이므로 프로젝트 격리가 필요할 때 공통 기본값으로 사용하지 않는다. 구체적인 RBAC 규칙은 계정·프로젝트가 정해진 뒤 검증한다. [공식 RBAC 문서](https://argo-cd.readthedocs.io/en/stable/operator-manual/rbac/)
- 개발자의 배포 변경은 Git을 경유한다. live override·임의 revision 배포·exec·리소스 action·삭제 권한을 편의상 추가하지 않는다. sync 권한이 필요하면 승인된 Git 상태 반영 범위로 검토하며 RBAC만으로 branch/revision 정책까지 보장한다고 설명하지 않는다.
- 계정/RBAC·Argo CD 자기관리 경로를 수정할 수 있는 Git 권한도 관리자 범위로 보호해야 한다. 일반 개발자가 자기 권한을 올리는 변경을 단독 반영하지 못하도록 리뷰·브랜치 보호를 별도 구성한다. 현재 보호 규칙이 적용된 상태는 아니다.

## 비밀값

비밀번호·저장용 비밀번호 해시·발급 토큰은 Git, values, 예제, 대화, 명령 인자에 넣지 않는다. [Doppler 지침](../../.agents/skills/k3s-infra/references/doppler.md)에 따라 보호된 원본과 주입 경로를 사용하고 각 계정의 자격 증명을 다른 개발자에게 노출하지 않는다. 실제 비밀값 전달·변경 이력은 Git의 계정/권한 변경과 구분한다.

Argo CD Secret에는 계정 외의 내부 키도 있으므로 계정 비밀번호 주입을 위해 전체 `argocd-secret`을 덮어쓰지 않는다. 실제 버전의 password/hash·변경 시각·토큰 필드와 Secret 소유권을 확인하고, 선택한 주입 방식이 내부 키를 보존하도록 설계·검증한다. Doppler Operator 등 동기화 도구는 아직 선정하지 않았다.

최초 admin 인증과 복구 인증은 대상 클러스터 밖에서도 확보할 수 있어야 한다. 비밀번호 발급·교체 절차는 별도 구현하며 임의 CLI/live patch로 GitOps 관리 원본을 우회하지 않는다.

## 최초 admin에서 개인 계정으로 전환

1. 최소 bootstrap 단계에서만 기본 admin으로 초기 설정한다. 기본 admin을 일상 운영이나 개발자 공유 로그인에 사용하지 않는다.
2. 개발자별 계정과 RBAC를 Git에 정의하고 보호된 비밀값 전달 경로를 준비한다. 플랫폼 관리 담당자의 개인 계정과 필요한 관리자 권한을 별도로 지정한다. 신규 계정은 비활성 상태로 준비하고 비밀번호 주입을 확인한 뒤 별도 Git 변경으로 활성화한다. 생성 values를 전체 설치 chart에서 렌더링하여 중복 소유권·권한 추가·override가 없는지 검증한다.
3. 개인 계정으로 새 로그인 세션을 열어 허용한 접근이 성공하고, 다른 프로젝트·권한 밖의 작업은 거부되는지 확인한다. 관리 담당자의 개인 계정도 실제 관리 기능을 검증한다.
4. Argo CD 자기관리·Git 접근·Doppler 주입과 클러스터 밖 복구 경로를 확인한다. 개발자 계정만 생성했거나 기존 admin 세션만 살아 있는 상태에서 다음 단계로 넘어가지 않는다.
5. 검증 후 별도 Git 변경으로 입력의 `phase=managed`, `cutover.verified_admin`, `cutover.recovery_verified`를 기록하고 values를 재생성하여 `admin.enabled: "false"`를 반영한다. 개인 계정 로그인·권한이 유지되고 admin 새 로그인이 거부되는지 확인한다. 기존 admin 토큰·세션의 처리도 실제 버전에 맞게 검증하며 설정 하나로 모두 폐기되었다고 가정하지 않는다.

Argo CD도 기본 admin의 초기 설정 용도 사용과 이후 로컬 계정/SSO 전환·admin 비활성화를 권장한다. [공식 계정 관리 문서](https://argo-cd.readthedocs.io/en/stable/operator-manual/user-management/)

## 추가 발급·권한 변경·회수

추가 발급은 계정 소유자·고유 계정명·담당 프로젝트·필요 권한을 확인한 뒤 Git 변경과 비밀값 전달, 로그인·허용/거부 검증 순서로 수행한다. RBAC는 선택한 Argo CD 버전의 정책 검증 도구와 실제 접근 검사로 확인한다. 문서 작성만으로 권한 검증을 완료했다고 보고하지 않는다.

퇴사·권한 회수 시 Git에서 해당 계정을 비활성화하고 권한 매핑을 정리한다. 발급 토큰·기존 세션·비밀번호 항목·Doppler 접근도 별도로 정리하고 재접속/API 접근이 거부되는지 확인한다. 계정 정의 삭제만으로 모든 자격 증명이 회수되었다고 가정하지 않는다.

잠금 사고가 발생하면 일반 앱 배포 권한을 확대하거나 기본 admin을 상시 켜 두지 않는다. [GitOps 복구 경계](../../.agents/skills/k3s-infra/references/gitops.md)에 따라 확인된 Git revision과 별도로 보호한 bootstrap/복구 인증으로 관리 접근을 복구하고 재검증한다.
